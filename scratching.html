Component 01 / Sound synthesis

Scratching synthesizer

A software model of turntable scratching based on record movement, sample position, playback velocity and cross-fader behavior.

Component owner: Michael Biggar

How it works

The instrument reads performance commands from the XML score and synthesizes scratching by moving through recorded sound.

Audio source

Recorded sample

CWaveLibrary provides audio data. The scratch instrument samples the recording at a continuously updated position instead of playing the full recording at normal speed.

Record movement

Motion model

The scratch controller determines a target playback velocity. Hand and motor parameters influence acceleration and the actual velocity used to move through the sample.

Cross-fader

Fader model

The fader opens and closes the audible signal. Its rate, open percentage, timing offset and response can shape short rhythmic cuts.

Scratch methods

The synthesizer implements five named scratching methods that are used in the XML score.

Baby

Slower forward and backward movement without rapid fader cuts.

Scribble

Faster back-and-forth motion with more frequent cycles.

Chirp

Coordinated movement and short fader openings.

Transform

Repeating fader taps create rhythmic interruptions to the scratch audio.

Orbit

Forward and backward record motion forms alternating scratch strokes.

Motor simulation

Velocity blends motor-driven motion with hand-controlled motion using configurable pressure and response.

Score parameters

XML attributes configure performance per note. The program assigns defaults to parameters not included in a note.

Configurable controls

  • sample, method: recording and scratch type.
  • startPosition, speed, cycles, stroke: movement through the recording.
  • faderRate, faderOpenPercentage, faderOffset: rhythmic gating.
  • handPressure, motorSpeed, handResponse, motorResponse: physical motion behavior.
  • attack, release, gain: amplitude shaping.

Example note

<instrument instrument="ScratchInstrument">
  <note measure="2" beat="1"
        duration="1"
        sample="are-you-ready.wav"
        method="scribble"
        startPosition="0.38"
        speed="1.5" />
</instrument>

How the scratching component meets the rubric

Our scratching synthesizer simulates turntable movement by controlling the speed and direction of recorded audio playback. XML parameters customize scratch patterns, crossfader timing, acceleration, and motor behavior. The implementation supports five techniques: baby, scribble, chirp, transform, and orbit. The table below shows how the code addresses each grading criterion.

PointsCriterionHow our implementation addresses it
10Audio playback on demand from the sequencerCSynthesizer::Generate() creates a CScratchInstrument when an XML note reaches its scheduled measure and beat. SetNote() selects the audio recording from CWaveLibrary; Generate() then produces one stereo frame at a time until the note ends.
20Attack, decay, and pitch variationThe amplitude envelope fades in and out using configurable attack and release. Playback position advances according to the current record velocity, so faster movement changes pitch. Output amplitude is also scaled by the absolute velocity to simulate a softer sound when the record moves slowly.
30Two scratch methodsThe instrument implements baby and scribble scratches through different default velocities and cycle counts. Baby scratches use slower strokes; scribble scratches use faster, repeated strokes. Both appear in scratch_demo.score.
35Four scratch methodsThe code supports five methods: baby, scribble, chirp, transform, and orbit. Chirp and transform modify the cross-fader timing, while orbit uses alternating forward and backward record motion. All five are included in the scratching demonstration.
40General parameterization of scratchingCScratchController generates motion from speed, cycles, stroke, and forward. Fader controls include faderRate, faderOpenPercentage, faderOffset, and faderResponse. A score can override the presets on individual notes to construct customized scratches without adding another hardcoded method.
50General method with motor simulationCScratchInstrument::Generate() blends the hand's target scratch velocity with motorSpeed using handPressure. handResponse and motorResponse determine how quickly the actual velocity approaches the target, modeling acceleration and deceleration rather than instantaneous jumps.

Evidence for the 40- and 50-point levels

These two levels depend on how record motion is generated, not simply on having five named scratch presets.

40 points / Parameterized scratching

One controller, adjustable performances

GetTargetVelocity(time) computes a forward and reverse motion cycle. The stroke parameter sets what fraction of the cycle is the forward stroke; cycles controls the repetitions; speed changes the playback rate; and forward reverses the direction.

Separately, GetTargetFader(time) controls rhythmic openings and closures. CFader smooths those changes using the configured response. In measure 4 of scratch_demo.score, two customized orbit notes vary the stroke, number of cycles, fader pattern, and playback direction.

50 points / Motor simulation

Hand motion and motor motion interact

For each generated sample frame, the code calculates:

targetVelocity =
  (1 - handPressure) * motorSpeed
  + handPressure * scratchVelocity;

It then moves the current velocity gradually toward that target using an exponential response based on handResponse, motorResponse, and sample period. The sample position is advanced by the resulting velocity.

Measure 5 of scratch_demo.score compares handPressure="1" (no motor contribution) with handPressure="0.65" and motorSpeed="1.0" (motor motion contributes 35% of the target).
